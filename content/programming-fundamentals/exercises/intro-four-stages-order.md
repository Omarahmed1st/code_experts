## Question

Programming goes through four stages. Which list puts them in the right order?

## Options

- [ ] Write the code → understand the problem → design the solution → test and improve
  Writing code first means writing it without a plan. You can't plan steps for a problem you don't understand yet.
- [x] Understand the problem → design the solution → write the code → test and improve
  Right: think first (understand, then design), then code, then test with real values and fix mistakes.
- [ ] Design the solution → write the code → understand the problem → test and improve
  You can only design a solution after you know what goes in, what must come out and what the rules are.
- [ ] Understand the problem → write the code → test and improve → design the solution
  The design (for example a flowchart or pseudocode) comes before the code, not after it.

## Hints

- What must you know before you can plan any steps?
- The lecture's tip says: good programmers think first, then code.

## Explanation

The four stages are:

1. **Understand** the problem: what goes in, what must come out, and what the rules are.
2. **Design** the solution: plan the steps, for example with a flowchart or pseudocode.
3. **Write** the code in a programming language.
4. **Test and improve**: run it with real values, find mistakes and fix them.

Typing code is only one part of programming. Most beginner bugs are mistakes in the plan, so the thinking stages come before the coding stage.
