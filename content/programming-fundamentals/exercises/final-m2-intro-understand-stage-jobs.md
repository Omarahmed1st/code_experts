## Question

Programming goes through four stages: **understand** the problem, **design** the solution, **write** the code, **test and improve**.

**Problem:** a phone company charges for each minute of a call. Write a program that shows how much credit is left after a call.

Which of these jobs belong to the **first** stage, *understand the problem*? Pick **all** of them.

## Options

- [x] Asking whether the credit can have piastres, such as 12.75 pounds.
  Right: this is a rule about the input. You need to know it before you can plan anything, because it decides what kind of numbers the program works with.
- [x] Finding out what must appear on the screen at the end: only the credit left, or a message too.
  Right: knowing exactly what must come out is part of understanding the problem.
- [ ] Writing the steps as pseudocode: `INPUT credit`, `INPUT minutes`, `left ← credit - minutes * price`.
  This is the **design** stage. You can only plan the steps after you know the inputs, the outputs and the rules.
- [ ] Running the finished program with a call of 0 minutes to check that the credit does not change.
  This is the **test and improve** stage. It needs a program that already exists, so it comes last.

## Hints

- The first stage happens before any plan or code exists. Which jobs could you do with only the problem in front of you?
- In the first stage you find what goes in, what must come out, and the rules.

## Explanation

The first stage, **understand the problem**, answers three questions: what goes **in**, what must come **out**, and what the **rules** are. No plan and no code exist yet.

- Asking whether the credit can have piastres is a question about the input and its rules, so it belongs to the first stage.
- Deciding what the screen must show at the end is about the output, so it also belongs to the first stage.
- Writing pseudocode is **design**, the second stage: it plans the steps, and you can only plan once you understand the problem.
- Running the program with 0 minutes is **testing**, the last stage: there is nothing to run until the code is written.

Good programmers think first, then code. Skipping the first stage usually means writing code that solves the wrong problem.
